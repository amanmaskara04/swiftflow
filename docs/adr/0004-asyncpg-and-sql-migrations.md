# ADR 0004 — asyncpg with explicit SQL, and plain SQL migrations

**Status:** accepted · 2026-11-14

## Context
The guide suggests SQLAlchemy and Alembic. The interesting parts of this system (conditional updates, `SKIP LOCKED`, RLS settings, `ON CONFLICT`) are SQL features, and interviewers ask about them directly.

## Decision
Use asyncpg with hand-written, parameterised SQL in small repository modules. Migrations are ordered `.sql` files applied by `swiftflow_common.migrate` under an advisory lock.

## Consequences
- The SQL that guarantees correctness is visible and reviewable in one place.
- No ORM change tracking; repositories return plain dataclasses or Pydantic models.
- No autogenerated migrations; each is written and reviewed by hand. Forward-only, with expand-then-contract for breaking changes.
